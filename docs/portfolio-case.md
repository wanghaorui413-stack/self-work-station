# 秋招作品集讲法

## 一句话介绍

我做了一个本地优先的每日均衡计划系统，用来解决雅思备考和科研并行时容易偏科、拖延弱项、单项任务占满全天的问题。

## 项目动机

我发现自己每天要做的任务并不少，但真实问题不是“不知道任务是什么”，而是执行结构不稳定：擅长或紧急的事情会吞掉整天，不擅长的模块会被长期跳过。所以我没有只做一个普通 To-do List，而是把重点放在“均衡分配”和“反馈闭环”上。

## 我的设计

我把任务拆成雅思输入、雅思输出、词汇和科研几类，每类设置最低保障时间，剩余时间按权重分配。科研被拆成两段，避免变成无限任务。对于弱项任务，我设计了 5 分钟启动机制，先降低启动阻力。

V2 进一步加入近 7 天统计：系统会根据本地完成记录识别薄弱模块、计算完成率和连续均衡日，并给出策略提醒。

## 可展示能力

- 产品思维：从真实痛点出发，明确用户场景和核心约束。
- 数据意识：不是只记录完成状态，而是用历史数据识别偏科模式。
- 规则建模：将“均衡学习”转化为最低保障、权重分配和完成率计算。
- 工程能力：完成静态网页、状态管理、本地存储、测试和文档。
- 迭代意识：从 V1 每日计划升级到 V2 数据闭环，并保留后续路线图。

## 面试表达模板

> 这个项目最初来自我自己的备考和科研并行场景。我发现普通任务表只能告诉我今天要做什么，但不能防止我一整天只做一类任务。因此我设计了一个本地优先的均衡计划系统：先根据当天可投入时间生成计划，每类任务有最低保障，科研拆成两段；执行上提供 5 分钟启动来降低弱项回避；V2 又加入近 7 天统计，识别哪个模块经常被跳过，并给出调整建议。这个项目体现了我把真实问题拆成产品规则、再用代码实现和验证的能力。

## 可以放进简历的写法

- 独立设计并实现 Daily Balance Planner，一个本地优先的学习/科研计划系统，通过“最低保障时间 + 权重分配”算法自动生成每日计划，解决多任务并行下的执行失衡问题。
- 引入近 7 天本地数据统计，计算完成率、连续均衡日和薄弱模块，并基于跳过次数生成策略提醒，形成从计划、执行到复盘的闭环。
- 使用原生 HTML/CSS/JavaScript 实现计时器、浏览器通知、本地存储和响应式界面，并编写 smoke test 验证核心分配与统计逻辑。
