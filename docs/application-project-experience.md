## 简历条目（3-5 条，按需取舍）

- **独立设计并开发本地优先的桌面个人工作台**（Electron + 原生 JS），整合日程、待办、周日历、招聘进度和每日时间分配，数据只存在本机，不依赖云端账号。
- **用大模型自动处理招聘邮件**：Claude 定时任务每天两次读取招聘邮件，抽取面试、测评、AI 面试等事项，写成结构化 JSON；信息含糊的标为“待核对”，改期邮件更新原事项而不是重复新建。另外实现了邮件解析接口：用 JSON Schema 约束模型输出，再用规则二次校验（要求模型摘抄写明时间的原文并核对确实出现在邮件里，时间缺失、含糊或早于收信时间的一律转人工核对），解析结果经用户确认后才写入日程。
- **设计时间约束下的自动排程算法**：固定日程先占住时间（含准备、缓冲和交通），截止任务自动排进截止前最早的整块空档（避开饭点，尽量不拖到截止当天），剩余空档按“最低保障 + 权重”分给用户自定义的投入方向；空档不够时按优先级取舍，用户手动固定的时段优先占位，其他时段绕开它重新排。
- **做成常驻的桌面应用**：托盘常驻、开机自启、Windows 系统通知（面试前一天和开始前 1 小时、截止前 24 小时提醒）；周日历支持拖选时间段新建日程、右键编辑删除、按日期跳转，待办可以一键转成会自动排期的截止任务。
- **用领域建模和自动化测试保证可维护性**：维护领域词汇表和 4 份架构决策记录（ADR）；排程、提醒、数据接口和邮件解析校验都有自动化测试；旧版浏览器数据可以无损迁移到新的本地存储。

## 300 字版本

秋招期间，我同时要准备雅思、做科研、跟进多家公司的面试和测评，经常遇到两个问题：招聘邮件里的时间容易漏，以及一整天被某件事占满、其他重要方向长期停滞。为此我独立开发了 Self Work Station。

招聘信息部分，Claude 定时任务每天两次读取招聘邮件，把面试、测评提取成结构化事项；我还实现了邮件解析接口，用 JSON Schema 约束模型输出，再用规则校验模型引用的原文和时间，拿不准的交给用户核对，不让模型编造的时间进日程。排程部分，我设计了分层的约束排程：固定日程先占时间（含准备、缓冲、交通），截止任务排进截止前最早的空档，剩余时间按“最低保障 + 权重”分给自定义的投入方向，用户也可以手动固定时段。产品以 Electron 桌面程序常驻，提供今天时间轴、周日历、待办、7 日复盘和系统通知。工程上，我用领域词汇表和架构决策记录（ADR）管理设计，并用自动化测试覆盖排程、提醒和数据接口。

## 项目难点（面试常问）

1. **怎么把“均衡推进”变成能计算的规则？** 每个方向有最低保障时间和权重；空档不够时先保住标了“优先保留”的方向。“被挤占”和“主动跳过”分开统计，弱项识别才不会被冤枉。用户手动固定的时段先当作占用时间，其他时段绕开它排。
2. **两个写入方怎么共用一个数据文件？** 定时任务和工作台都写 `items.json`。我按字段划分各自能改的部分，服务端用字段白名单加串行化的原子写入，避免互相覆盖；用户手动建的、粘贴解析建的事项用 `source` 标记，定时任务不能动，也只有这两类能删除（邮件来的删了下次同步还会再建，所以只能取消）。
3. **大模型抽取的结果不可靠怎么办？** 三层防线：JSON Schema 约束输出格式；规则校验要求模型给出写明时间的原文片段，并核对它确实出现在邮件里，链接也必须在原文中；时间缺失、只写了“下周”、或早于收信时间的，一律标成待核对，由用户补全后才排进日程。解析接口本身不写数据，用户在预览里确认后才保存。
4. **为什么从网页改成桌面程序？** 网页版要另外跑一个后台服务器，服务没开时页面就不可用。改成 Electron 后，数据接口在主进程里运行，托盘常驻和系统通知也更可靠。这个取舍记录在 ADR 0003 里。

## 被问到时如实说明

- **隐私脱敏还没做**：邮件发给模型之前没有去掉签名、电话。自己用没问题，开放给其他用户之前要补上（ADR 0004 里有记录）。
- **评估**：`evals/extract/cases.json` 是合成的标注邮件，用来检查各字段抽取是否正确，不是真实用户数据。
- **日常邮件同步仍走 Claude 定时任务**，解析接口是为以后开放给其他用户准备的，现在通过“粘贴邮件”入口使用。
