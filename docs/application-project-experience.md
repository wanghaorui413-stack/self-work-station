## 300 字版本

面向雅思备考与科研工作并行时容易出现的任务失衡问题，我独立设计并实现了 Daily Balance Planner。项目不是普通 To-do List，而是围绕“如何保证每天各类重要任务都至少推进一次”进行规则建模：系统根据用户设置的专注总时长、开始时间和休息边界，采用“最低保障时间 + 权重分配”的方式自动生成计划，并将科研拆成两个深度工作区块，避免单一任务占满全天。

在执行层面，我为每个任务设置今日小目标、完整计时和“先做 5 分钟”启动按钮，用来降低口语、写作等弱项任务的启动阻力。V2 版本进一步加入 7 日反馈闭环，基于浏览器本地记录统计平均完成率、连续均衡日、完成专注时长和薄弱模块，并生成策略提醒。项目使用原生 HTML/CSS/JavaScript 实现，数据保存在 localStorage 中，并通过 Node.js smoke test 验证时间分配、页面引用、跨午夜时间和历史统计逻辑。

## 500 字版本

Daily Balance Planner 是我为雅思备考和科研工作并行场景设计的本地优先任务均衡系统。项目起点来自一个真实执行问题：当每天同时存在单词、听力、阅读、口语、写作和科研任务时，普通任务表只能列出“要做什么”，但很难避免用户一整天只做熟悉或紧急的任务，导致弱项长期被跳过。因此我将项目目标定义为：帮助用户每天保持多模块推进，并通过本地数据识别偏科和回避模式。

在产品设计上，我将任务分为雅思词汇、输入训练、输出训练和科研深度工作几类。系统根据用户选择的总专注时长、开始时间、短休息和午间长休息，使用“最低保障时间 + 剩余时间按权重分配”的规则生成当天计划。科研任务被拆成两个区块，避免它变成没有边界的无限任务；口语和写作等弱项任务则提供“先做 5 分钟”按钮，降低启动阻力。

在 V2 版本中，我加入了 7 日反馈闭环：系统基于浏览器 localStorage 中的本地记录，统计平均完成率、连续均衡日、已完成专注时长和各模块完成分布，并根据跳过次数识别薄弱模块，生成面向执行调整的提醒。这样项目从“生成计划”进一步扩展为“计划—执行—记录—复盘”的闭环工具。

在工程实现上，我使用原生 HTML/CSS/JavaScript 完成响应式界面、任务计时器、浏览器通知、本地存储和统计看板，并使用 Node.js 编写 smoke test，验证核心时间分配、DOM 引用、跨午夜显示和历史统计逻辑。项目同时补齐 README、产品设计说明、架构说明、路线图和截图，使其可以作为秋招作品集项目展示。

## 网申可拆分填写

### 项目描述

设计并实现一个本地优先的每日任务均衡系统，面向雅思备考与科研并行场景，通过自动排期、计时提醒、5 分钟启动和 7 日统计，解决单项任务占满全天与弱项任务长期回避的问题。

### 主要职责

1. 拆解用户执行痛点，定义任务失衡、弱项回避和缺少反馈三个核心问题。
2. 设计“最低保障时间 + 权重分配”的时间分配规则，并将科研拆分为两个深度工作区块。
3. 使用原生前端实现计划生成、任务计时、本地保存、浏览器提醒和响应式界面。
4. 加入近 7 天统计看板，识别薄弱模块并生成策略提醒。
5. 编写测试和项目文档，使项目具备可演示、可复盘和可维护性。

### 项目难点

- 如何把“均衡推进”这种模糊目标转化为可执行的时间分配规则。
- 如何在不引入后端的情况下完成历史记录和统计反馈。
- 如何让工具不只服务打卡，还能针对弱项回避给出可执行提醒。

### 项目亮点

- 从真实个人场景出发，有明确用户痛点和产品假设。
- 使用本地优先设计，保护隐私并降低部署复杂度。
- 从 V1 计划表迭代到 V2 数据闭环，体现持续优化能力。
- 具备测试、截图、README 和系统文档，适合作为作品集展示。
