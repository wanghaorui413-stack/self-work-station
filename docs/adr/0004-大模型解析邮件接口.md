# 0004 提供“邮件 → 事项”的大模型解析接口

- 状态：已接受
- 日期：2026-11-03

## 背景

招聘邮件现在靠 Claude 定时任务处理：Gmail 转发 + 每天两次读取，写进 `data/items.json`。这套流程只适合自己用，它依赖桌面端 Claude 开着、依赖个人邮箱授权，没法给别人用，抽取效果也没法单独测。

## 决定

- 工作台提供 `POST /api/extract`：输入一封邮件（标题、正文、收信时间），调用 Claude API（`claude-opus-5-5`）返回候选事项。**只解析，不写数据**；用户确认后再走 `POST /api/items/extracted` 保存。
- 用结构化输出（JSON Schema）约束模型的输出格式，回来后再用代码规则核对一遍（`scripts/extract.mjs` 的 `validateExtraction`）。以下情况一律标成待核对，不直接排进日程：
  - 缺开始 / 截止时间，或模型自己标了“含糊”“缺失”；
  - 时间早于收信时间一天以上（多半是年份推错）；
  - 模型摘抄的“写明时间的原文”在邮件里找不到（时间可能是编的）。
  - 邮件里没出现过的链接直接丢掉。
- 模型只负责理解，默认值（时长 60 分钟、AI 面试 45 分钟）和状态判断都由代码决定，规则和定时任务一致（见 docs/recruiting-data.md）。
- 保存的事项带 `source: "paste"`，算招聘事项，但定时任务不会改动它们。
- 自己用时邮件仍走 Gmail 转发 + 定时任务，不变；页面上的“粘贴邮件解析”用于手头的单封邮件和演示。以后开放给其他用户时，在这个接口前面接上他们的邮箱即可。
- API 密钥只放在本机：环境变量 `ANTHROPIC_API_KEY`，或 `data/llm.json` 的 `anthropicApiKey`。不进 Git，也不发给页面。没配置时接口返回 503，其他功能照常。
- 抽取效果用 `evals/extract/cases.json` 的标注邮件衡量（`npm run eval:extract`，按字段统计准确率）。自动化测试用假的模型客户端，不需要密钥。

## 考虑过的其他方案

- **让模型直接写 items.json**：省一步确认，但模型出错会直接进日程，而且和定时任务抢着写同一个文件。
- **只靠提示词要求输出 JSON**：格式偶尔会坏；结构化输出能保证可解析，省掉重试逻辑。
- **在接口里直接接 IMAP 收信**：自己用不需要（已有 Gmail 流程），给别人用时邮箱授权方式还没定，先把“给一封邮件，返回事项”这个核心能力做扎实。

## 后果

- 多了一个依赖 `@anthropic-ai/sdk`，调用按量计费，费用由使用者自己的 API 密钥承担。
- 邮件正文会发给 Anthropic API。目前不做脱敏，粘贴前由用户自己决定内容；开放给其他用户前要补上脱敏和隐私说明。
- 模型因安全分类拒绝时，由服务端回退到其他模型重试（`fallbacks: "default"`）；仍然拒绝就返回明确的错误。
