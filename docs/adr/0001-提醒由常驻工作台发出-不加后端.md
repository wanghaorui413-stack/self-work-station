# 0001 提醒由电脑上常驻的工作台发出，不加后端

- 状态：已接受
- 日期：2026-11-01

## 背景

工作台要提醒用户面试、测评等招聘事项的时间点。用户每天都会用电脑，不需要手机提醒。现有项目是纯静态、local-first 的单页应用，提醒靠浏览器 Notification API，页面一关就失效。

## 决定

- 提醒由电脑上常驻的工作台网页发出（Windows 系统通知）。工作台随开机自启、常驻后台。
- 读邮件、提取事项交给外部的 Claude 定时任务（每天 8:30、18:30 各一次）：163 邮箱自动转发到 Gmail，定时任务读取 Gmail，把事项写进一个私密 Gist。
- 工作台本体继续是无后端的静态页面：从 Gist 读取事项，在本地排时间、发提醒，并把“已完成”等状态写回 Gist。

## 考虑过的其他方案

- 手机日历订阅 .ics（小米需借助 ICSx⁵）：Gist 域名在国内不稳定，同步失败时用户察觉不到；用户也不需要手机提醒。
- 自建后端，推送到微信：需要常驻服务和运维，打破零后端定位。
- 本地脚本用 IMAP 直接收 163 邮件：数据不出本机，但事项提取质量受限于规则匹配。

## 后果

- 电脑关机或工作台没在运行时，不会有提醒。
- 招聘邮件会多存一份在 Gmail（经 163 转发），事项数据放在私密 Gist，链接即钥匙。
- 招聘事项的数据不能只存在 localStorage，工作台需要能读写 Gist。
