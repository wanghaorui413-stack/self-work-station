# 0002 所有用户数据统一存在本机 data/ 目录，不再用 localStorage

- 状态：已接受
- 日期：2026-11-02

## 背景

工作台正在从“雅思均衡计划器”扩展成个人工作台（见 GLOSSARY 中的“工作台”）。原来的数据分在两处：招聘事项在本机 `data/items.json`（ADR 0001），每日计划、完成记录、复盘和设置则在浏览器 localStorage 里。

localStorage 有三个问题：清除浏览器数据或换浏览器后记录就没了；Claude 和其他本地脚本读不到，以后没法根据历史给出建议；备份要分两处做。ADR 0001 之后，本地服务器已经开机常驻，“打开页面时服务器一定在”这个前提已经成立。

## 决定

- 投入方向、待办、手动建的事项、每日记录、设置，全部存在本机 `data/` 目录下，由本地服务器通过 `/api` 读写，沿用 ADR 0001 的原子写入和串行写入。
- localStorage 只保存无关紧要的界面状态，例如当前打开的是哪个视图。
- 首次升级时，把 localStorage 里已有的每日记录迁移进 `data/`，原有 6 个雅思和科研类别变成 6 个普通的投入方向，历史统计不中断。
- GitHub Pages 上的演示版不连服务器，只用内置的样例数据。

## 考虑过的其他方案

- **保持 localStorage，只加导出和导入**：改动最小，但数据仍然不稳，Claude 也读不到。
- **IndexedDB**：容量更大，但同样锁在浏览器里，其他问题都还在。
- **SQLite**：查询能力强，但要引入原生依赖，打破零依赖；而当前的数据量用 JSON 文件就够了。

## 后果

- 不开本地服务器时，工作台只能看演示，不能使用。双击 `index.html` 直接打开的方式不再支持正式使用。
- 备份就是复制 `data/` 文件夹。
- 本地服务器的接口和测试会明显变多。
